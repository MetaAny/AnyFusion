# 任务命令与 TUI 用户体验优化清单

> 创建日期：2026-07-13  
> 状态：待逐项评估和实施  
> 用途：记录本轮关于命令、执行器交互和前端展示的讨论结论，后续按清单逐项优化。  
> 说明：文中的命令名称仅用于表达能力候选；除已经存在的命令外，不代表最终命令路径已经确定。

## 总体判断

应该增加常见任务指令。应该支持“指定执行器”，但要区分“咨询执行器”和“派发任务给执行器”。不建议提供完全绕过 PlanningAgent、ControlKernel 和任务审计的“裸执行器通道”。

前端当前最大问题不是配色，而是展示依赖字符串、缺少结构化状态和可执行下一步。

## 1. 现有命令描述与实际效果对齐

### 1.1 命令盘点

- [√] 逐项盘点当前已经注册的命令、子命令、参数、默认行为和别名。
- [√] 检查帮助文案中展示的命令是否都有真实处理分支。
- [√] 检查已经存在的能力是否都能在帮助中被发现。
- [√] 检查命令缺参、参数错误和未知子命令时的提示是否准确。
- [√] 检查命令示例是否可以按展示方式直接执行。

### 1.2 描述与副作用

- [ ] 每条命令明确说明它是只读查询、状态修改、任务调度还是 Executor 操作。
- [√] 文案描述实际副作用，不能用模糊描述掩盖缺失实现。
- [√] 对暂停、阻塞、取消、完成和批量清理，确认是否会真正停止对应 Executor。
- [√] 对恢复和解除阻塞，确认是否会自动重新调度任务。
- [√] 对关联材料、记忆修改、配置查看等命令，确认输出与真实持久化结果一致。
- [ ] 统一用户侧术语和语言，避免帮助、usage、错误信息中英文混杂。

### 1.3 单一命令契约

- [√] 让命令说明、usage、参数、示例、补全和执行来自同一份命令定义。
- [√] `/help` 不再维护独立的硬编码命令清单。
- [√] 前端不再维护另一份静态命令建议列表。
- [√] 对状态相关命令提供可用性判断和不可用原因。
- [√] 用测试保证帮助中展示的命令与实际可执行命令一致。

## 2. 常见任务能力候选（仅做参考，不是任务清单，不一定做最终实现）

> 本节记录应该补充的能力，不提前锁定最终命令路径、一级快捷入口或别名。

### 2.1 高频任务控制

- [ ] 显式创建任务：用户可以明确要求创建并规划一个任务。
- [ ] 状态总览：快速查看当前运行、排队、暂停和阻塞情况。
- [ ] 可靠停止或暂停：保存恢复信息并停止实际执行。
- [ ] 取消任务：保留审计记录，同时停止对应执行。
- [ ] 恢复任务：从暂停或阻塞状态继续，并说明恢复依据。
- [ ] 重试任务：建立新的执行轮次，不覆盖原失败记录。
- [ ] 当前焦点：明确后续自然语言和材料补充默认作用于哪个任务。

### 2.2 任务调度与队列

- [ ] 查看任务队列、预计下一个任务及不可执行原因。
- [ ] 调整任务优先级，并确保真实影响调度。
- [ ] 设置或清除截止时间，明确时区和绝对时间。
- [ ] 支持人工调整队列顺序，并记录调整原因。
- [ ] 区分“禁止同时执行多个任务”和“禁止创建待执行任务”。

### 2.3 可解释性与结果查询

- [ ] 解释任务为什么被选择、阻塞、暂停或排在当前位置。
- [ ] 查看任务产物、来源 Executor 和验证状态。
- [ ] 查看任务状态变化、调度、执行和恢复事件。
- [ ] 支持归档任务，但保留历史、审计和检索能力。

## 3. 指定执行器与直接交互

### 3.1 指定执行器派发任务

- [ ] 允许用户指定 Executor 执行正式任务。
- [ ] 指定 Executor 仍然需要创建或继续正式 Task/Execution Attempt。
- [ ] 派发仍需经过 PlanningAgent、ControlKernel、任务准入、材料注入和审计。
- [ ] Executor 不存在、不可用或能力不匹配时，展示原因和可选 Executor。

### 3.2 咨询执行器

- [ ] 将“咨询 Executor”与“派发正式任务”明确区分。
- [ ] 咨询默认不修改任务状态、不写文件、不触发正式调度。
- [ ] 如需关联任务上下文，应显式指定关联任务。
- [ ] 咨询模式必须有可靠的只读权限约束，不能只依赖提示词。
- [ ] 咨询结果仍需记录关联 Executor、任务上下文和权限模式。

### 3.3 执行器交接

- [ ] 支持把任务后续工作交给另一个 Executor。
- [ ] 交接创建新的执行轮次或后续子任务，不覆盖历史记录。
- [ ] 新 Executor 接收已有结果、失败原因、材料、快照和用户补充说明。

### 3.4 明确边界

- [ ] 不提供绕过 PlanningAgent、ControlKernel、Task Persistence 和 Execution Runtime 的裸 Executor 通道。
- [ ] 前端明确区分普通对话、Executor 咨询、正式任务派发和任务交接。
- [ ] 在权限、审计和上下文边界没有设计清楚前，不上线直接 Executor 对话能力。

## 4. 前端展示优化

### 4.1 命令发现与补全

- [ ] 输入 `/` 后按领域展示命令，而不是只展示固定的一级列表。
- [ ] 支持逐层补全子命令和可枚举参数。
- [ ] 展示参数名、允许值、示例和实际效果。
- [ ] 根据当前任务状态过滤不可执行操作，或明确展示不可用原因。
- [ ] 区分只读查询、状态修改和高风险操作。

### 4.2 当前焦点与输入状态

- [ ] 持续展示当前焦点是普通对话、某个任务还是无焦点。
- [ ] 持续展示当前输入状态，例如意图理解、任务 follow-up 或 Executor 注册向导。
- [ ] 让用户知道当前自然语言预计会直接回复、创建任务还是继续已有任务。

### 4.3 运行状态

- [ ] 展示当前任务、Executor、执行阶段、当前子任务、运行时间和进度。
- [ ] 展示 ready 队列中的前几个任务、优先级和顺序。
- [ ] 展示 blocked/parked 原因、缺失条件和可复制的恢复入口。
- [ ] 最近事件优先展示用户可理解的重要状态变化。

### 4.4 结果与下一步

- [ ] 状态修改结果展示原状态、新状态和实际影响范围。
- [ ] 明确说明 Executor 是否已停止、快照是否已保存、任务是否重新调度。
- [ ] 任务结果展示摘要、产物、验证状态和可执行下一步。
- [ ] 失败结果区分可重试、缺材料、缺权限、Executor 不可用和不可恢复失败。
- [ ] Suggested Actions 使用结构化数据，而不是拼接到普通输出字符串中。

### 4.5 高风险操作与空状态

- [ ] 批量清理、取消运行任务和强制派发前展示影响预览并要求确认。
- [ ] 确认状态由结构化 Session State 管理，不依赖输出字符串判断。
- [ ] 新会话展示自然语言、任务创建和状态查询示例。
- [ ] 存在未完成任务时，启动页优先展示可恢复和阻塞任务。
- [ ] 明确提示 `/`、`/help`、方向键和补全键的用途。

### 4.6 结构化展示模型

- [ ] 将 Session 输出逐步迁移为结构化 View Event/ViewModel。
- [ ] 结构化事件包含 taskId、executorName、timestamp、severity 和 suggestedActions。
- [ ] TUI 不再依赖具体中文前缀和符号判断输出类型。
- [ ] TUI、飞书和未来 Web UI 消费同一套结构化语义，各自负责渠道渲染。

### 4.7 长结果浏览

- [ ] 为任务历史、审计和其他长命令结果设计独立的可折叠、可滚动结果面板。
- [ ] 明确结果面板与命令补全候选框的职责边界、焦点切换、滚动键位和关闭行为。
- [ ] 在结果面板完成前，长历史查询采用明确的条数上限和截断提示。

## 5. 测试与验收

- [ ] 每个现有命令至少覆盖一个真实成功场景，不只断言输出文本。
- [ ] 状态修改命令断言 Task 状态、Executor 中断、持久化和调度副作用。
- [ ] 覆盖用户中断与 Executor 迟到结果之间的竞态。
- [ ] 覆盖帮助、解析、参数校验和自动补全的一致性。
- [ ] 覆盖 TUI 中目录节点、缺参命令、动态引用和逐层补全。
- [ ] 覆盖 TUI 与飞书对关键结构化状态的展示一致性。

## 6. 建议实施顺序

1. 先盘点现有命令，修正文案、帮助和真实副作用。
2. 再统一命令契约、解析、帮助和补全。
3. 修复暂停、取消、清理和迟到结果竞态。
4. 补充高频任务控制、队列和可解释性能力。
5. 升级前端状态、下一步提示和高风险确认。
6. 在权限与审计模型明确后，再实现指定 Executor、咨询和交接。
